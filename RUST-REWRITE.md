# Native runtime status

The Rust rewrite is complete. Rust is the sole CLI runtime; Node/pnpm are
contributor tooling, not a product installation or fallback. Native archives,
managed installation and explicit upgrade are supported. Current usage belongs
in [the user guide](USER-GUIDE.md), ownership in [Architecture](ARCHITECTURE.md),
and verification commands in [Development](DEVELOPMENT.md).

## Supported boundaries

- Names are unique within the selected local database. Plain pane-bound
  identities are temporary; saving promotes the same UUID. Retirement preserves
  retained exchanges. Folders and worktrees do not create identity namespaces.
- Replies are immutable exact bodies in SQLite, not terminal captures.
  Local receipts correlate recorded requests and endpoints; they are not remote
  authentication. [Request/response](REQUEST-RESPONSE.md) owns the wire and
  attention contracts.
- Native schema migrations are forward-only from supported historical schemas. Old
  TypeScript/schema-8 writers must stop before migration and cannot reopen
  native state. Binary rollback does not imply database downgrade.
- The native installer does not migrate or delete application data. Existing
  package-manager installations require the explicit replacement instructions
  in the user guide; no mixed-runtime continuity is promised.
- Source changes do not replace immutable published assets. Archive/bootstrap
  acceptance is distinct from raw executable smoke checks; see
  [release verification](docs/native-release-verification.md).
- No daemon, memory service or remote-work implementation is implied by native
  runtime support. Office is a separate optional application.

## Maintained verification owners

| Boundary                                                          | Evidence owner                                                                                                          |
| ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Grammar, identity, configuration, profiles and X output           | [Native process tests](test/native/) and owner-local Rust tests                                                         |
| Real caller/pane lifecycle, delivery uncertainty and full replies | [Docker scenarios](test/e2e/) with independent state/event oracles                                                      |
| Transactions, concurrent finalization and crash recovery          | [Storage adapter tests](rust/crates/tmt-adapters/src/storage/) and [request service](rust/crates/tmt-core/src/request/) |
| Historical migrations and old receipt inputs                      | [Frozen fixture provenance](test/fixtures/storage-history/README.md), never regenerated by current migrations           |
| Runtime selection and tooling boundaries                          | [Shared selector](test/support/cli-executable.mjs) and [tooling tests](test/tooling/)                                   |
| Dependency direction and module ownership                         | [Native architecture guard](rust/crates/tmt-cli/tests/architecture.rs), supplementary to review                         |
| Measured startup and scoped latency                               | [Performance evidence](PERFORMANCE-BASELINE.md), not a throughput or universal speedup guarantee                        |

The [scenario ownership map](DEVELOPMENT.md#scenario-ownership) distinguishes
native process and Docker evidence. Test counts, returned-error rollback and
cross-compilation cannot substitute for crash, real-process or platform proof.
